## 🧠 RAM YÖNETİMİ DÜZELTMESİ (2026-08-07 — AlwaysPreTouch bulgusu)

**Durum:** `ps`'te 58GB VSZ görünüyor ama gerçek (RSS) 15.6GB — VSZ sanal rezervasyon, sorun değil. Asıl şişkinlik: `-XX:+AlwaysPreTouch` → Java açılışta 10G heap'in tamamını fiziksel kilitleyip sisteme geri vermiyor + 400+ mod native belleği + Rusticl OpenCL derleme önbelleği (~5.6GB).

**Çözüm (mod gerekmez — mod yok, çünkü JVM heap tavanı açılışta sabitlenir; "RAM booster" modları sahtedir/zararlıdır):**
```bash
# run.sh'te:
-Xms4G -Xmx10G   # açılışta 4G kilitle, ihtiyaç arttıkça 10G'e kademeli büyü
# AlwaysPreTouch'u ÇIKAR (asıl suçlu)
# küçülme için:
-XX:MinHeapFreeRatio=20 -XX:MaxHeapFreeRatio=40 -XX:G1PeriodicGCInterval=60000 -XX:+G1PeriodicGCInvokesConcurrent
```
**Etki:** açılışta ~4GB kilitlenir, yük arttıkça büyür, boştayken G1 küçültüp sisteme iade eder → "gerektiği kadar kilitleme" davranışı.

**Ek: Rusticl/OpenCL native önbelleğini sınırla (5.6GB'in bir kısmı):**
```bash
# Mesa shader önbelleği boyut sınırı (MB):
export MESA_SHADER_CACHE_MAX_SIZE=512
# run.sh'e ekle veya /etc/environment'a yaz
```
**Not:** `-Xmx`'i 9G/8G'e çekmek de geçerli ama yukarıdaki ayar asıl "dinamik" davranışı verir; Xmx 10G kalsın (yük anlarında gerekebilir). Swap 36GB zaten OOM güvencesi.
